# Master Project Documentation: Enterprise Multi-Agent AI System

## 1. Executive Summary
**Project Name**: Enterprise Multi-Agent AI System (Document & PPT Generation POC)
**Purpose**: An AI-powered platform for generating, analyzing, and interactively editing Microsoft Word and PowerPoint documents via natural language.

**30-Second Explanation (Executive/Business)**: 
The Enterprise Multi-Agent AI System automates the creation of professional business proposals and presentations. By securely ingesting corporate templates and knowledge bases, the platform ensures consistent branding and formatting while using AI to instantly generate high-quality, fully editable drafts. Its conversational editing feature lets users effortlessly refine documents, drastically cutting the time and cost associated with manual report generation.

**Technical Explanation**:
This platform is a micro-orchestrated multi-agent system consisting of 10+ specialized agents coordinated by a sequential Supervisor. It features a native Python-based OpenXML generation engine (`core/ooxml_docx.py`, `core/ooxml_pptx.py`) allowing in-place, deterministic edits to `.docx` and `.pptx` files based on structured JSON commands generated by LLMs. The default LLM provider is a local Ollama instance (`qwen3:4b`), with optional Gemini support. Grounding is provided through an internal RAG pipeline (using local n-gram/hash embeddings and SQLite). Live web search is also supported, but requires Gemini to be configured; it is skipped when running locally via Ollama. The architecture decouples probabilistic intent parsing (LLM) from deterministic file manipulation (Python OpenXML), ensuring document integrity and schema compliance.

## 2. Business Problem
**Manual Document Creation**: Employees spend hours manually formatting, copy-pasting, and styling proposals or presentations. 
**Template Inconsistency**: Enforcing corporate brand guidelines across large teams is difficult, leading to fragmented visual identities.
**Research Overhead**: Gathering accurate and up-to-date information requires switching contexts between the web, corporate drives, and the document editor.
**The "Un-editable AI Output" Problem**: Most generative AI tools produce PDFs or raw text, requiring users to manually rebuild the document or presentation. This system solves this by generating native, fully editable DOCX and PPTX files.

## 5. End-to-End Workflow
1. **Upload**: User uploads `Company_Proposal.docx` and `Company_Template.pptx`.
2. **Analysis**: `DocumentAnalysisAgent` and `PptAnalysisAgent` extract fonts (e.g., Georgia), brand colors (`#1B365D`), and layouts.
3. **Prompt**: User submits request.
4. **Research**: `WebResearchAgent` executes search (if Gemini is used). `EnterpriseRagAgent` queries local `knowledge_store.db`.
5. **Generation**: `ContentWriterAgent` generates sections and slides.
6. **Formatting**: `DocumentGenerationAgent` and `PptGenerationAgent` map the content to the extracted styles using the OpenXML engine.
7. **Validation**: `ValidationAgent` verifies XML integrity, slide counts, and citation inclusion.
8. **Storage/Preview**: Artifacts are saved to `output/` and `session.json` is updated. 
9. **Interactive Edit**: User highlights a paragraph and types "Make this red." The backend resolves the target, the LLM emits a JSON command (`update_style`, `color: FF0000`), and the deterministic editor applies it.

## 7. Current Implementation Status vs Production Readiness
Currently, the system is a **highly capable Proof of Concept (POC) / MVP**. 
- **LLM**: Gemini API is supported; local Ollama is supported but slower for large structured JSON.
- **RAG**: SQLite with local hashing is used. **Production requires Pinecone, Weaviate, or pgvector.**
- **Orchestration**: Static, sequential pipeline. **Production could benefit from LangGraph for dynamic routing.**
- **Security**: No authentication, local file paths used. **Production requires RBAC, S3 object storage, and strict path validation.**
